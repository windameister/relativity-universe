# 迭代历史

本文按时间顺序记录：做成了什么、发起人纠正了什么、试玩发现了什么、后来为什么改。数字和用例来自仓库里的试玩报告与统计，不是事后印象。

时间大致在 2026 年 11 月中旬（太平洋时间）。更早的构想没有单独的设计文档，是长期挂在心里的想法，在对话里被重新提出后才做成这个原型。

## 0. 构想被提出来

发起人希望做一个程序化、用数学建模的近真实银河沙盒：恒星、黑洞、星团、星云；星际旅行；真实的相对论时间膨胀（一趟旅行可以让宇宙过几百年，船上只过很短的时间）；文明自行演化；玩家可以当探索者、文明构建者、角色或飞行员。

同时希望世界按《三体》的宇宙法则运转：歌者 / 神级文明、黑暗森林、二向箔、宇宙维度坍缩；并要有真正动画起来的 3D 宇宙渲染，尤其是二维化和光粒打击。

## 1. 第一版 2D 原型：宇宙会自己走

先做成单文件的 2D 网页原型（后来的 `prototype/index.html`）。

这一阶段建立了至今还在用的骨架：

- 用种子生成银盘局部、地球和若干外星文明
- 文明每年按人口 / 科技 / 资源 / 稳定度演化
- 玩家旅行时不逐年实时模拟，抵达时一次性把外部年份推完（惰性求值）
- 地图和远程消息遵守光延迟
- 接触按科技差分层，黑暗森林、歌者、二向箔、黑域、维度流失都进了模拟

早期试玩记录见 `playtest/playthrough-sample.txt`（`test_sim.js` 对若干种子的文本输出）。当时已经能看到：回家时地球改了名字或已经死寂、先进文明拦截并抽走星图、远处出现降维闪光和归零者广播。

展示图：`assets/screenshots/screenshot.png`、`screenshot-map.png`、`screenshot-gift-echo.png`。

## 2. 物理被纠正：曲率不是超光速

发起人明确纠正了航行规则，这些后来写进了模拟内核的注释，正式版不得再改回去：

- 曲率驱动**不超过 c**，只是把飞船推到 c 或任意接近 c
- 时间膨胀必须按真实相对论（洛伦兹 γ）计算，船上时间非常短
- 常规推进无论什么能源都不可能接近 c
- 互动必须取决于科技差，不能所有文明共用一套选项

实现上的结果：

- 常规推进：0.01c / 0.03c，γ ≈ 1，舰员冬眠，衰老 1/50
- 曲率驱动：0.999c / 0.9999c / 0.99999c，清醒航行，留下航迹暴露
- 外部时间永远 ≥ 距离 / c；船上时间 = 外部时间 / γ
- Node 与 Chrome 若直接用 `Math.sin` / `Math.exp` 等，末位差会在几百年后变成完全不同的历史，所以模拟改用一套只用加减乘除和平方根的确定性数学

## 3. 3D 视图：同一宇宙，换一种看见的方式

在不分裂模拟内核的前提下，用 Three.js r187 做了 3D 页 `index3d.html`。源文件在 `prototype/src3d/`：`g3d.js` 负责场景和回放，`build.py` 从 `index.html` 复制模拟和界面，替换 2D 地图。

3D 里已经有：银盘与星云、曲率尾迹、光粒逼近和冲击、二向箔扩张、黑域、熄灭恒星的余烬，以及离开期间的时间压缩回放。恒星的高度只是视觉上的银盘厚度（约 ±7 光年），航程和光延迟仍按模拟里的平面距离计算。

## 4. 第一轮玩家试玩（r1–r4）

用无头 Chrome 真实点按钮，打了 4 局（谨慎探索、假扮神明、乱广播、长眠者），另加 150–200 个种子的统计。完整报告：`playtest/REPORT.md`。

**已经成立的体验：**「几百年后回来，一切都变了」很频繁。统计里 67% 的回访有明显变化。回家发现地球被征服、再回去太阳已被压成画、读到歌者「一首随手哼出的歌」；礼物可能让一个文明过早暴露；冬眠一千年醒来，地球自己成了黑暗森林猎手。这些都是后来坚持要保留的瞬间。

**最大的问题是「到访即死刑」：**曲率进出各加 0.6 暴露，合计 1.2，超过歌者阈值 1.0，而且暴露度锁在最大值不衰减。曲率到访的外星文明 600 年内被打击约 77%，留下少量技术后约 98%，没去过的对照约 19%。假扮神明的宗教后果几乎看不到，因为对方活不到那一天。文案却常把锅甩给「礼物」，真正的凶手（航迹）不提，玩家学不会规则。

其他尖锐问题：后期先进文明 55% 都是同一堵「拦截墙」；飞船科技涨太慢；崩溃和改名刷屏；选择几乎不影响历史；冬眠是免费时光机；母星被压平这种大事埋在远方消息里；若干硬 bug（被二维前沿追上后仍显示抵达、在家冬眠被自己人拦截、死寂星系反复被光粒击中、二维化显示成「已死寂」、贸易说明泄露母星当前名违反光延迟）。

截图：`playtest/r1-earth-flat.png`、`r1-final-map-god.png`、`r3-dead-but-arrived.png`、`r4-home-intercepts-own-ship.png`。

这一轮给出的改进优先级，后来基本都还有效：先让暴露和因果可读，再重做先进文明接触，让礼物和神话长出复杂回响，大事单独成卡，给长眠和补给加代价。

## 5. 第 5 轮修复：让因果可读，让 3D 能看

针对第一轮报告做了玩法和视觉修复，统计见 `playtest/FIXES-r5.md`、`stats-after-curse.txt`、`stats-after-tier.txt`。

关键变化：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 曲率到访的外星文明 600 年内被打击 | 72% | 37%（对照 14%） |
| 曲率到访 + 留少量技术 | 96% | 38%（对照 12%） |
| 曲率到访 + 广播坐标 | 100% | 100%（广播仍然几乎必死，这是规则） |
| 同一星系被光粒击中 ≥ 2 次 | 15–66 例 | 0（当时统计） |
| 后 8 站里「先进」层级占比 | 55% | 16% |
| 先进文明里「拦截墙」占比 | 100% | 30%（其余是冷漠 / 商人 / 收藏家 / 学者 / 通行 / 礼遇 / 官僚） |
| 回访里提到你造成的后果 | 0% | 73% |
| 大事件卡片 | 0 | 245 / 2216 次抵达 |
| Node 与 Chrome 结果 | 不一致 | 5 个种子 × 8 步 + 3000 年逐字一致 |

暴露度改为按来源分开记账、各自衰减，不再锁最大值。回访报告开始写出「你的曲率航迹 / 你交出的星图 / 你的广播 → 被谁在哪年看到 → 打击」。被二维追上不再错误地显示抵达；在母星冬眠不再被当成入侵者拦截。

设计判断：打击率降下来不是为了「变简单」，而是为了让死亡变成可学习的选择。广播坐标仍然 100% 引来清理，说明危险还在。

## 6. 第二轮玩家试玩（round 2）

4 个新种子：外交家、传教士、拾荒者、末日广播者，2D / 3D 都玩了。完整报告：`playtest/round2/REPORT-r2.md`。

结论：已经从「机制原型」变成「有叙事骨架的原型」，但还没到「每局都是不同故事」。

最好的瞬间：

- 回家，太阳系被压平，卡片写「你再也没有家可以回了」，因果句把锅落到玩家某次曲率出发上（`A-home-flat-causal.png`）
- 被当成恶魔的部落，300 年后孩子们过「驱魔节」，戴着照你的飞船做的面具
- 3D 回放里三片二向箔次第落下，时间流速从 ×87 骤降到 ×0.3（`D3d-replay-14.png`、`B3d-replay-foil1.png`）
- 冬眠 1000 年醒来，邻居是被「地球文明的深空监听网」清理的（`C-home-killed-neighbor.png`）

新的天花板也很清楚：

- 回响是线性阶梯和模板句（「泊位」「星图做生意」一局能刷 8 次），只交换过技术也会提到星图
- 盟友变成屠夫、地球成为猎手、流亡舰队不认人，这些线索断在半路，游戏没有把故事讲完
- 补给和回家太宽松，最低补给 75，「回家睡觉」能把飞船科技从 60 睡到 110，比拾荒和考古更优
- 传教线太脆：刚改扮神明，34 年后部落就被光粒抹掉；统计里 73% 的神眷文明 1500 年内灭亡
- 3D 好看，但无事件的回放仍要放好几秒「暂时风平浪静」；二维化看起来像彩色泡泡；回放不计光延迟，和核心规则打架

这一轮明确提出：应该上一个规则化、由历史条件驱动的事件库，并先做四条线——盟友 / 贸易伙伴变成屠夫、母星成为猎手、流亡者认人、宗教分叉树。同时要把「你的间接责任」写进因果句，收紧补给经济，给重大时刻做仪式感演出。

## 7. 事件库设计，然后做第一阶段

先写了设计稿（现为 `docs/EVENT_LIBRARY_DESIGN.md`）。三个关键决定：

1. **史实库是唯一的叙事真相。** 「谁在何时对谁做了什么」都记成带时空坐标的史实；谁能知道由光延迟统一计算。
2. **物理留在代码里，叙事和离散决策交给数据。** 事件只能通过封闭的操作符改状态，不能写任意脚本。
3. **事件用独立的确定性随机流。** 新增一个纯文本事件不会改变宇宙物理史。

设计把工作分成 P1–P5。先做 P1：引擎 + 把回响、后代舰队、大事件卡片迁成数据。P1 做完后，加剧情不必再改模拟代码。

## 8. 第 6 轮：事件库 P1 + 四条故事线（当前版本）

实现记录：`playtest/FIXES-r6.md`。事件源：`prototype/events/events_src.js`（90 个事件）。

做成的结构：

- 史实日志 `u.facts`；事件可在 year / pending / fact:* / arrival / recognize / report / choice 时触发
- 独立随机流 `hrand`，不消耗宇宙物理用的 `u.rs`
- 知识按光延迟传播；后裔只继承分家前的历史
- Node 工具：`tools/simload.js`、`tools/evcheck.js`、`tools/plan.js`

四条线已能在游戏里走出来：

- **间接因果**：例如「你 192 年给的曲率理论……」最后导致一场清理
- **盟友变屠夫**：交换过技术的文明后来用光粒抹掉别人；再见面时它认出你的飞船，可以调停、质问、站队或广播它的坐标
- **母星成了猎手**：回家能读到地球的清理档案，被清理文明的流亡舰队会来复仇
- **流亡者认出你**：你帮过的文明，后代可能报恩、怪你，或向你索要星图
- **宗教分叉**：伪先知、教会分裂、圣战、殉道者、朝圣者；可以选择祝福或告诉他们真相
- **代价**：飞船停在被光粒打中的恒星旁会有生命危险；冬眠按钮显示醒来时的年龄、会不会老死

回响不再刷屏：重复率从 49% 降到 11%。交换技术、贸易、结盟各写各的话；没给过星图就不会再说星图。

同时修掉了第二轮报告里的一串 bug，例如：太阳被压平后不再继续「被征服」或「去清理别人」；讲述时按光延迟统计见过的文明；冬眠 300 年不再显示成 299；3D 回放会单独演出归零者广播；「继续 / 离开」不再消耗随机数；补给已满时不再写 +30。

自测中还修了一些事件库自己引入的问题：计划不能强行选当前没有的选项；扣押不再被记成「结怨」从而错招复仇舰队；过期的打击预警不再弹卡；回响框不再重复已经出现过的句子。

交付时又作为玩家玩了两局，结局都和早先的选择对得上。有一局假扮神明，那个文明从伪先知走到圣战，最后仍被歌者抹掉，而歌者是顺着玩家自己的曲率航迹找过去的。

截图：`playtest/r6-a-ally-butcher.png`、`r6-b-home-hunter.png`、`r6-d-faith-3d.png`、`r6-3d-zero-broadcast.png`。

## 9. 交到本仓库时仍未解决的问题

事件库第一阶段结束后，发起人觉得「已经越来越有意思了」，希望整理需求、迭代和改进点，在本机用更强的模型做成更好玩、渲染更逼真震撼的正式版。当时仍指出的问题：

1. **宗教线走得太稳**：约 99% 的神眷文明都能走到中段剧情，路线却大多一样，很少走到改革派和使者号
2. **卡片偏多**：平均每局大约 6 张，一份报告里有时会叠 4 到 5 张
3. **有 10 个事件在 300 局覆盖率测试里从未触发：** `ally.mediate`（调停），`recog.demand` / `recog.give_maps` / `recog.refuse`（流亡者索要或拒给星图），`rel.god_to_devil`、`rel.answer_silence`、`rel.keep_faith`、`rel.endorse`，以及 `warn.evacuate` / `warn.evac_go`（打击到来前组织撤离）。整理本仓库时用当前代码重跑 `node tools/evcheck.js --n 300`，仍是这 10 个，覆盖率 80/90。
4. **有 13 种史实被写下来，却没有后续事件再读取：** `echo_gs2`、`echo_gl3`、`mediated`、`mediate_failed`、`questioned`、`sided`、`refugee_bcast`、`refugee_spurned`、`reparation`、`fleet_met`、`faith_martyr`、`faith_blessed`、`warned`。等于若干因果链只写了一半（例如调停成功就算发生了，也没有后续事件去用它）
5. 需再确认「同一恒星反复被光粒击中」是否完全消失（r5 统计曾降到 0，仍作为观察项）
6. 再往后：补给经济、3D 回放节奏

这些问题的处理建议见 `docs/03-ROADMAP.md`。

## 10. 几条值得保留的设计判断

- **惰性求值是对的。** 旅行不是即时战略，抵达时再结算，既符合「外面过了很久」，也让模拟可以在浏览器里跑完整局。
- **光延迟不是装饰。** 它让「你以为的家」和「家现在的样子」裂开，这是这个游戏特有的感情来源。
- **打击必须可归因。** 「到访即死刑」不可玩，不是因为太难，而是因为玩家学不到规则。广播仍然该死，航迹必须衰减，文案必须说真话。
- **模板句会迅速耗尽新鲜感。** 「驱魔节的面具」比「科技 +1.5」或「港口留了一个泊位」有力得多。事件库要写具体的人、仪式和年份。
- **物理和叙事要分开。** 加一段剧情不应该改写宇宙史；这是独立随机流和事件数据化的原因。
- **3D 是同一宇宙的眼睛，不是另一套游戏。** 改模拟只改 `index.html`（以及事件源），再生成 3D 页。
